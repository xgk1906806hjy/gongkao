# 09 · AI 分析 — 逻辑说明

## 1. 模块职责

基于考生资料、公告库与刷题数据，提供：

1. **简历选岗**：解析简历 → 评估报考优势 → 推荐在招考试与岗位方向
2. **复习计划**：按考试日期与各模块正确率生成阶段 / 每日 / 每周计划
3. **备考问答**：自由提问报考、备考、面试问题

## 2. 关键代码

| 路径 | 说明 |
|---|---|
| `server/internal/ai/client.go` | OpenAI 兼容 Chat Completions 客户端（JSON 模式、容错解析） |
| `server/internal/service/ai.go` | 资料、简历分析、计划、问答、限额、报告存储 |
| `server/internal/service/ai_rules.go` | 规则引擎：简历字段抽取、公告打分、专业→岗位方向、规则计划、FAQ |
| `server/internal/handler/ai.go` | HTTP 接口 |
| `miniapp/pages/ai/*` | 小程序「AI 备考助手」（入口：我的、刷题页） |
| `web/app.js` `renderAI` | Web 预览 |

## 3. 双引擎设计

- **规则引擎**（始终可用、零成本）：先跑一遍得到结构化结果
- **大模型**（配置 `AI_API_KEY` 后启用）：在规则结果基础上优化
  - 简历：把规则排序后的前 15 条候选公告交给模型重排，模型只能从候选 ID 中选，非法 ID 丢弃
  - 计划：把规则草案交给模型细化，`exam_date / days_left / daily_hours` 以规则值为准；返回不完整则弃用
- 模型超时 / 报错 / 当日超额 → 回退规则结果，并通过 `notice` 告知用户
- `provider` 字段标明结果来源（模型名或 `rule`）

## 4. 主流程

### 简历选岗 `POST /ai/resume/analyze`

1. 合并请求中的表单字段 → 规则抽取简历（学历、专业、届别/应届、政治面貌、工作/基层年限、证书、意向地区）
2. 候选公告：已发布、报名未截止、近 180 天（或缺发布日期）、标题为招聘类（排除公示/成绩/名单/提示等）、可按考试类型过滤
3. 打分：地区、报名状态、应届/选调、党员、基层经历、学历门槛、专业关键词、遴选限制、时效
4. （可选）大模型重排与生成评语
5. 保存资料与报告

### 复习计划 `POST /ai/study-plan`

1. 考试日期优先级：请求 → 资料 → 「我的考试」最近考试 → 默认 90 天
2. 统计各分类答题数、正确率、未掌握错题数 → 诊断（数据不足 / 薄弱 / 一般 / 较好）
3. 分阶段：≥60 天 基础/强化/冲刺；20~59 天 强化/冲刺；<20 天 冲刺
4. 每日模板：错题复盘 10%、申论（仅事业单位时为综合应用）20%，其余按模块权重 × 薄弱系数分配
5. 周计划最多 12 周

## 5. 数据

| 表 | 说明 |
|---|---|
| `ai_profiles` | 每用户一条资料（含简历原文，上限 8000 字） |
| `ai_reports` | 每次分析结果（`kind`=resume/plan/ask，`output` 为 JSON） |

## 6. 配置

`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`、`AI_TIMEOUT`（默认 60s）、`AI_DAILY_LIMIT`（默认 30 次/人/天，仅统计大模型调用）。

## 7. 边界与注意

- 公告未结构化职位表，推荐粒度为「考试公告 + 岗位方向」，结果均提示以职位表为准
- 简历属于个人信息：仅本人可读；`DELETE /me/ai/profile` 一键删除资料与全部报告；简历原文不在分析结果中回传
- 简历目前支持粘贴文本；PDF/Word 上传解析未实现
- 小程序请求超时已调至 90s 以适配大模型响应
