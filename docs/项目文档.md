## 1. 项目概述

### 1.1 产品定位

面向公务员、事业单位等公考备考用户的**微信小程序**，打通：

**公告浏览 → 加入我的考试 → 代办提醒 → 刷题 / 时政学习**

解决信息分散、报名/确认/考试节点易遗漏、刷题与时政割裂的问题。

### 1.2 本期能力概览

| 能力 | 说明 |
|---|---|
| 微信登录 | `wx.login` → 后端换会话；本地 `WX_MOCK` 可免 AppID |
| 考试公告 | 公务员 / 事业单位；列表筛选、详情时间线；定时外网采集 |
| 我的考试 / 代办 | 加入后自动生成报名/确认/考试代办；到期前约 10 分钟提醒 |
| 订阅消息 | 用户授权后由 Worker 发送；未授权不推送 |
| 刷题 | 分类练习、顺序/随机、作答看解析、交卷、错题本再练、统计 |
| 时政 | 外网 RSS 采集；标签筛选、详情、收藏、阅读记录 |
| 管理 API | 公告/题目/时政维护、CSV/JSON 导题、采集失败查看（无可视化后台） |

### 1.3 明确不做（Out of Scope）

- 支付 / 会员 / 直播 / 一对一辅导
- 模拟面试、申论批改、AI 评分
- 原生 App、公众号 H5 独立产品
- 可视化运营后台（仅管理 API）
- 岗位表 PDF 深度结构化入库

## 3. 技术架构

### 3.1 逻辑架构

```text
┌─────────────────┐     HTTPS/HTTP      ┌──────────────────┐
│  微信小程序       │ ─────────────────► │  cmd/api (Gin)   │
│  miniapp/       │ ◄───────────────── │  JWT / CORS      │
└─────────────────┘                     └────────┬─────────┘
                                                 │
         ┌───────────────────────────────────────┼────────────────┐
         ▼                                       ▼                ▼
   PostgreSQL / SQLite                        Redis           微信开放平台
   (业务数据)                              (提醒 ZSET)      code2session
         ▲                                       ▲           订阅消息
         │                                       │
         └────────────── cmd/worker ◄────────────┘
                    采集 cron / 提醒扫描 / 可选每日时政推送
```

### 3.2 进程职责

| 进程 | 入口 | 职责 |
|---|---|---|
| API | `server/cmd/api` | HTTP REST、鉴权、业务读写、管理接口；启动时可跑一次采集种子 |
| Worker | `server/cmd/worker` | 每分钟处理到期提醒；约每 30 分钟采集；可选每日 08:00 时政推送 |
| crawlonce | `server/cmd/crawlonce` | 本地一次性采集验证（不常驻） |

API 与 Worker **同属一个 Go module**，分开进程是为了：不阻塞 C 端请求、独立扩缩与故障隔离。

### 3.3 技术选型

| 层级 | 选型 |
|---|---|
| 客户端 | 微信原生小程序（WXML/WXSS/JS） |
| 服务端 | Go 1.25、Gin、GORM |
| 数据库 | 生产推荐 PostgreSQL 16；本地可用 SQLite（`sqlite:xxx.db`） |
| 缓存 / 延时队列 | Redis 7（提醒 ZSET `todo:remind`；Redis 不可用时回退 DB 扫描） |
| 鉴权 | JWT（access + refresh）；管理员独立 token 类型 |
| 部署 | Docker Compose（postgres / redis / api / worker） |
| 浏览器预览 | `web/` 静态页（非正式客户端） |

## 5. 核心业务与数据流

### 5.1 登录鉴权

1. 小程序 `wx.login` 取 `code`
2. `POST /api/v1/auth/wechat` → 后端 `code2session`（或 MOCK）→ upsert 用户
3. 返回 `access_token`、`refresh_token`、用户资料；`session_key` 仅服务端加密存储
4. 受保护接口带 `Authorization: Bearer <access>`
5. 401 时客户端尝试 `POST /auth/refresh`，失败则清 token 并重新登录

管理员：`POST /admin/login`（默认见环境变量），使用 admin 类型 JWT 访问 `/admin/*`。

### 5.2 公告 → 我的考试 → 代办

1. C 端浏览已上架公告（`status=published`）
2. 详情页「加入我的考试」→ `POST /me/exams`
3. 后端按公告时间线生成代办（缺字段则跳过该节点）：
   - 报名截止 / 开始
   - 资格确认截止 / 开始
   - 参加考试
4. 每条代办：`remind_at = due_at - 10 分钟`，写入 Redis ZSET（及 DB）
5. 离开考试：取消未完成代办并移出 ZSET
6. 管理端修改公告时间线：同步刷新该公告下用户未发送提醒的代办

### 5.3 微信订阅提醒

```text
用户授权订阅 → POST /me/subscribe-prefs { todo: accept }
       ↓
Worker 每分钟扫描 remind_at <= now
       ↓
校验：代办 pending + 用户 accept + 模板已配置
       ↓
wx 订阅消息 SendSubscribe → remind_status=sent
失败有限重试（默认最多 3 次）；未授权 → skipped
```

**真机推送前置条件：**

| 条件 | 说明 |
|---|---|
| `WX_MOCK=false` | 关闭模拟发送 |
| `WX_APPID` / `WX_SECRET` | 小程序凭证 |
| `WX_SUBSCRIBE_TEMPLATE_TODO` | 已审核模板 ID |
| 用户点「允许」 | 小程序 `requestSubscribeMessage` |
| Worker 进程在跑 | `start-dev.ps1` 或 `go run ./cmd/worker` |

本地默认 `WX_MOCK=true`：只打日志，手机收不到真消息。

### 5.4 刷题

1. `POST /practice/sessions`：`mode=sequential|random|wrong`，可选 `show_analysis`
2. 答题过程：`POST /practice/check` 返回对错、正确答案、解析（不提前泄露）
3. `POST /practice/submit` 判分、写入错题本、更新会话
4. 错题本支持再练（`mode=wrong`）与移除
5. `GET /me/practice/stats`：累计题量、正确率、近 7 日趋势

### 5.5 时政

- 列表支持 `tag`、`keyword` 分页
- 详情（可选登录）记录阅读
- 登录用户可收藏 / 取消收藏
- 可选每日推送：`AFFAIRS_DAILY_PUSH_ENABLED=true` + 时政模板 + 用户 accept

## 6. 数据模型（要点）

由 GORM `AutoMigrate` 维护，核心实体：

| 实体 | 说明 |
|---|---|
| `users` | 微信用户；含加密 `session_key` |
| `admin_users` | 管理员（bcrypt 密码） |
| `announcements` | 公告；`type=civil\|institution`；时间线字段；`source+source_id` 去重 |
| `user_exams` | 用户加入的考试（user+announcement 唯一） |
| `todos` | 代办；`status` / `remind_status` / 重试计数 |
| `user_subscribe_prefs` | 订阅授权：`todo` / `affairs` × `accept\|reject` |
| `question_categories` / `questions` / `question_options` | 题库 |
| `practice_sessions` / `user_answers` / `wrong_questions` | 练习与错题 |
| `affairs_articles` / `affairs_favorites` / `affairs_reads` | 时政 |
| `crawl_failures` | 采集失败记录 |

## 7. 采集子系统（Crawler）

### 7.1 调度

- Worker：`CRAWLER_ENABLED=true` 时启动执行一次，之后约 **每 30 分钟**
- API 启动：也会跑一次（便于本地只有 API 时也有数据）
- 手动：`cd server && go run ./cmd/crawlonce`

### 7.2 内置源

| Source 名 | 类型 | 说明 |
|---|---|---|
| `cpta` | 公告 + 时政 | 中国人事考试网首页链接（`/notice/`、`/examNotice/`、`/currentAffairs/` 等） |
| `gov-zhengce` | 公告 | `https://www.gov.cn/zhengce/zuixin/ZUIXINZHENGCE.json`，按招考关键词过滤 |
| `xinhua-politics` | 时政 RSS | 新华网时政 |
| `people-politics` | 时政 RSS | 人民网时政 |
| `xinhua-legal` | 时政 RSS | 新华网法治 |
| `seed-*` | 演示 | 仅当 `CRAWLER_SEED_FALLBACK=true` **且尚无外网数据** 时写入 |

可通过 `CRAWLER_AFFAIRS_RSS_URL` / `CRAWLER_AFFAIRS_RSS_URLS`（逗号分隔）追加时政 RSS。

### 7.3 合规与策略

- 优先摘要 + **原文链接**，正文不全量镜像站点
- 采集失败写入 `crawl_failures`，可用管理 API 查看并以人工录入兜底
- 站点改版可能导致解析失败，需观察 Worker 日志与失败表

## 10. 本地开发与部署

### 10.1 Windows 一键开发

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-dev.ps1
powershell -ExecutionPolicy Bypass -File scripts/smoke.ps1
```

脚本会：检测/尝试启动 Redis → 编译 `api`/`worker` → 后台拉起 → 健康检查 → 起 `web` 预览（`:5173`）。

日志目录：`server/logs/api.*.log`、`server/logs/worker.*.log`。

### 10.2 分步启动

```bash
# 基础设施
cd deploy && docker compose up -d postgres redis

# 后端
cd server
copy .env.example .env   # 并改 DATABASE_URL 为 Postgres
go mod tidy
go run ./cmd/api
# 另开终端
go run ./cmd/worker
```

### 10.3 Docker 全栈

```bash
cd deploy
docker compose up -d --build
```

服务：`postgres`、`redis`、`api(:8080)`、`worker`。

### 10.4 小程序联调

1. 微信开发者工具打开 `miniapp/`
2. 详情 → 本地设置 → 不校验合法域名
3. 确认 `baseURL` 指向本机 API
4. 真机调试还需：合法域名、HTTPS、正式 AppID、关闭 MOCK

### 10.5 采集自测

## 13. 运维与排障

| 现象 | 排查 |
|---|---|
| API 起不来 | 看 `server/logs/api.err.log`；检查端口 8080、`.env`、数据库文件/连接 |
| 提醒不发 | Worker 是否运行；Redis/DB；用户是否 `todo=accept`；模板 ID；`WX_MOCK` |
| 公告/时政为空 | 跑 `crawlonce`；看 `crawl_failures`；外网是否可达；`CRAWLER_ENABLED` |
| 小程序 401 | token 过期；refresh 失败后重新登录；`baseURL` 是否正确 |
| Docker 起不来 | Docker Desktop 状态；`docker compose logs api worker` |

生产建议：HTTPS、更换全部密钥、关闭 MOCK、配置正式订阅模板与 request 合法域名、Postgres + Redis 高可用、限制管理接口暴露面。

## 14. 当前成熟度与后续方向

### 14.1 已具备

- M1～M4 主路径可演示：登录、公告代办提醒链路、刷题、时政、管理 API
- 真实公开源定时采集（人事考试网 + 政府网过滤 + 主流时政 RSS）
- 订阅偏好门禁、代办 UX、刷题解析与错题再练等 P0 补齐项

### 14.2 已知限制

- 公告采集以列表/摘要 + 原文链接为主，时间线字段未必总能自动填全（可人工编辑后同步代办）
- 政府网关键词过滤近期可能命中较少，人事考试网为主要公告来源
- 无可视化运营后台；限流、refresh 黑名单等为 P1
- 真机订阅依赖微信侧审核与用户一次性授权

### 14.3 建议后续

1. 按省份扩展招考公告 HTML/RSS 插件
2. 公告详情页增强时间线解析（从正文抽取报名/考试时间）
3. 管理端简易 Web 后台
4. 生产观测：采集成功率、提醒到达率仪表盘
5. 安全加固：接口限流、密钥轮换、审计日志
