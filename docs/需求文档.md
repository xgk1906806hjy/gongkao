## 1. 背景与目标

### 1.1 背景

公考（公务员、事业单位等）备考用户需要持续跟踪各地招考公告、管理报名/确认/考试节点，并配合刷题与时政学习。信息分散、时间节点易遗漏，缺少「公告 → 个人考试计划 → 提醒 → 刷题/时政」一体化工具。

### 1.2 产品目标

1. 聚合公务员、事业单位考试公告，支持浏览与筛选。
2. 用户可将公告加入「我的考试」，自动生成报名、确认、考试等代办。
3. 代办到期前 10 分钟通过小程序订阅消息提醒用户。
4. 提供刷题（题库练习、错题本、基础统计）与时政阅读（列表、详情、收藏）。
5. 支持微信一键登录与鉴权，保障账号与数据安全。

### 1.3 成功指标（上线后观察）

| 指标 | 说明 |
|---|---|
| 登录成功率 | 微信登录接口成功率 ≥ 99% |
| 公告覆盖 | 首期至少稳定接入 1～2 个可公开采集源 + 人工补录通道 |
| 代办提醒到达 | 已授权订阅的用户，提醒任务投递成功率 ≥ 95% |
| 刷题完成率 | 开始练习后完成交卷的比例（基线建立后迭代） |
| 时政阅读 | 人均阅读篇数、收藏率（基线建立后迭代） |

## 2. 范围说明

### 2.1 本期范围内（In Scope）

- 微信小程序端全部 C 端功能（见第 5 章）。
- Go 后端 REST API、PostgreSQL 持久化、Redis 缓存与提醒队列。
- 公告自动采集（可配置源）+ 管理端人工录入/审核兜底。
- 完整刷题：分类练习、判分、错题本、简单统计、题库批量导入。
- 时政：抓取/发布、列表详情、收藏、阅读记录；可选每日订阅推送。
- 代办提醒：订阅消息 + 到期前 10 分钟投递。

### 2.2 本期范围外（Out of Scope）

- 微信公众号 H5 独立产品（本期不做；公众号仅可作为后续引流入口）。
- 支付、会员充值、课程直播、一对一辅导。
- 模拟面试、申论批改、AI 作文评分。
- 原生 App（iOS/Android）。
- 复杂运营后台前端（本期提供管理 API，可视化后台可二期）。
- 精确到「岗位表 PDF 解析入库存岗」的深度结构化（首期以公告级时间线为主）。

### 2.3 用户角色

| 角色 | 说明 |
|---|---|
| 考生用户 | 小程序普通用户，使用公告、考试、代办、刷题、时政 |

## 5. 功能需求

### 5.1 微信登录与鉴权

**编号**：F-AUTH

| 需求点 | 描述 | 优先级 |
|---|---|---|
| F-AUTH-01 | 用户打开需登录能力的页面时，可发起微信登录；调用 `wx.login` 获取 code，提交后端换取会话 | P0 |
| F-AUTH-02 | 后端通过微信 `code2session` 获取 openid（及可选 unionid），首次自动注册用户 | P0 |
| F-AUTH-03 | 登录成功返回 access token 与 refresh token；客户端后续请求携带 `Authorization: Bearer <access>` | P0 |
| F-AUTH-04 | access 过期可用 refresh 换新；refresh 失效则重新走微信登录 | P0 |
| F-AUTH-05 | 支持用户补充头像、昵称（微信头像昵称填写能力） | P1 |
| F-AUTH-06 | `session_key` 仅存服务端（加密字段或短期 Redis），不得下发客户端 | P0 |
| F-AUTH-07 | 未登录访问受保护接口返回 401；小程序引导登录 | P0 |

**验收要点**：

- 新用户首次登录落库一条 `users` 记录。
- 旧用户重复登录不产生重复 openid。
- 无 token / 假 token 无法访问 `/me/*`。

### 5.4 我的代办与提醒

**编号**：F-TODO

#### 5.4.1 代办生成规则

加入我的考试时，按公告字段生成代办：

| 代办类型 | 触发字段 | 默认 `due_at` | 标题示例 |
|---|---|---|---|
| `register` | `register_end`（若无结束则用 `register_start`） | 对应时间 | 报名截止/报名开始 |
| `confirm` | `confirm_end`（若无则用 `confirm_start`） | 对应时间 | 确认截止/确认开始 |
| `exam` | `exam_at` | 考试时间 | 参加考试 |

- `remind_at = due_at - 10 分钟`。
- 若某字段为空，则跳过该类型代办。
- 公告关键时间变更时：同步更新该用户下「未完成且未提醒成功」的对应代办的 `due_at` / `remind_at`。

#### 5.4.2 代办状态

| 状态 | 说明 |
|---|---|
| `pending` | 未完成 |
| `done` | 用户标记完成 |
| `cancelled` | 用户关闭或移除考试后取消 |

#### 5.4.3 功能列表

| 需求点 | 描述 | 优先级 |
|---|---|---|
| F-TODO-01 | 「我的代办」按公告分组展示事项、到期时间、倒计时 | P0 |
| F-TODO-02 | 用户可标记完成或关闭单条代办 | P0 |
| F-TODO-03 | 到期前 10 分钟触发提醒投递（订阅消息） | P0 |
| F-TODO-04 | 进入代办/考试相关页时引导用户授权订阅消息（一次性/按微信规则） | P0 |
| F-TODO-05 | 未授权订阅时：不推送，但列表内高亮即将到期项 | P0 |
| F-TODO-06 | 提醒发送状态可追踪：待发送 / 已发送 / 失败（含有限重试） | P0 |
| F-TODO-07 | Worker 基于 Redis ZSET（或等价延时队列）按分钟扫描到期 `remind_at` | P0 |

**验收要点**：

- 考试时间 10:00 → 提醒目标时刻 09:50。
- 已完成/已取消代办不再提醒。
- 无订阅授权不调用发送，不导致 Worker 死循环。

| Affairs | GET | `/affairs/:id` | 详情 | 否 |

| Affairs | DELETE | `/me/affairs/favorites/:id` | 取消收藏 | 是 |
| Admin | * | `/admin/*` | 运营管理 | 管理员 |

详细字段级 API 说明见后续 `docs/API.md`（实现阶段补充）。

## 7. 数据需求概要

### 7.1 核心实体

- `users`：openid、unionid、昵称、头像、时间戳
- `announcements`：类型、地区、标题、来源、URL、摘要/正文、报名/确认/考试时间、上架状态、采集元数据
- `user_exams`：用户与公告关联
- `todos`：类型、due_at、remind_at、状态、提醒发送状态、关联 user_exam
- `question_categories` / `questions` / `question_options`
- `practice_sessions` / `user_answers`
- `wrong_questions`
- `affairs_articles` / `affairs_favorites` / `affairs_reads`
- `admin_users`
- `crawl_failures`（采集失败记录）

### 7.2 关键索引

- `announcements(type, region, published_at)`
- `todos(user_id, due_at, remind_status)`
- `questions(category_id)`
- `users(openid)` 唯一

## 9. 提醒与订阅规则（业务说明）

1. 用户在「我的代办」或加入考试成功后的引导弹层中，调用 `wx.requestSubscribeMessage`。
2. 仅当用户授权对应模板后，Worker 才调用微信订阅消息发送接口。
3. 每条代办在 `remind_at` 触发一次主提醒；失败则有限次重试（建议最多 3 次，指数退避或固定间隔）。
4. 若用户未授权：应用内用样式标记「即将到期」（如 24 小时内），不承诺推送。
5. 时政每日推送为 P1，需单独模板与开关，默认关闭直至运营配置。

| 提醒时效 | Worker 宕机导致漏提醒 | 进程守护 + 启动时补偿扫描 DB 中到期未发送项 |

## 12. 验收总则

1. 需求条目优先级 P0 必须在对应里程碑演示通过。
2. 每个 P0 条目具备至少一条可重复的验收步骤（见各节「验收要点」）。
3. 真机订阅消息依赖微信侧配置；开发环境可用「模拟发送日志」验收 Worker 逻辑。
4. 本文档与实现冲突时，以评审后的需求变更为准，并更新本文档版本号。
